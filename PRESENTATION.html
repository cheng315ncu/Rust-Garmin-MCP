02 · Architecture

The GET pipeline.

Six layers. Each one earns its place. Cache hits skip everything below them.

Layer 6
Tool Layer
77 tools registered through #[tool_router] on GarminMcpServer. Each tool is a thin adapter over Arc<GarminApiClient>.
▼
Layer 5
ClinicalExport
FlatSummary · HrvPayload · TimeseriesArray · EventTable — one trait, four shapes, JSON or CSV at the output edge.
▼
Layer 4
moka Async Cache
60-second TTL · 1 000 entries · key is sorted endpoint?k=v. Singleflight via try_get_with — concurrent callers share one in-flight fetch. Cache hit = Arc<Value> bump, no Mutex, no network.
▼  cache miss
Layer 3
governor Rate Limiter
Token bucket · 60 req/min · shared across reads and writes. until_ready().await guards the per-session limit Garmin enforces but never documents.
▼
Layer 2
Rust Sync Layer
Mutex<GarminClient> for GETs (the upstream lib needs &mut self). RwLock<BearerToken> for writes — many readers, exclusive refresh. One pooled reqwest::Client reuses TLS + TCP.
▼
Layer 1
Garmin Connect API
GET via garmin_client · POST/PUT/DELETE via reqwest with bearer token. Successful writes call cache.invalidate_all() so the next read sees fresh data.

03 · Concurrency model

Type-safe sessions.
By construction.

The compiler refuses to ship a second OAuth session. There are three primitives. Each one solves a specific failure mode.

M

Mutex<GarminClient>

Garmin rate-limits per session token, and api_request needs &mut self. Serialising every GET through one Mutex is not a workaround — it’s the safety property.

R

RwLock<BearerToken>

Writes hold a read lock concurrently. Token refresh acquires the write lock with double-checked locking. One token; many concurrent POSTs.

H

reqwest::Client

One pooled HTTP client across every write path. TLS handshakes and TCP connections are reused — not re-paid on every tool call.

// src/client.rs · the entire shared session
pub struct GarminApiClient {
    inner: Arc<Mutex<GarminClient>>,        // GET · serialised
    http:  reqwest::Client,                  // writes · pooled
    token: Arc<RwLock<BearerToken>>,         // shared bearer
    cache: Cache<String, Arc<Value>>,        // moka · 60s TTL
    limiter: Arc<Limiter>,                   // governor · 60/min
}

04 · Cache & rate limit

Coalesce duplicates.
Respect the upstream.

60s
Cache TTL
Long enough to coalesce LLM re-asks. Short enough that fresh wearable data isn’t hidden.
1 000
Cache entries
LRU-evicted past the cap. Keys are sorted endpoint?k=v; values are Arc<Value> for cheap clones.
60/min
Rate budget
Token bucket via governor. Shared across reads and writes — one budget covers all Garmin-bound traffic.
1
In-flight per key
moka’s try_get_with deduplicates concurrent callers. Ten tools asking the same question = one network call.
 Why TTL caching

An LLM will ask the same question twice.

Within a single conversation, a model frequently re-fetches the same day’s sleep summary three or four times as it reasons. moka turns those repeats into Arc-bumps. The Mutex never sees them; the network never sees them.

 Why rate limit

Garmin’s limit is real but undocumented.

Burst traffic from a chatty agent can trigger a per-session lockout that affects your phone, watch, and web app simultaneously. governor enforces a conservative ceiling — write-side included — so sustained agent use stays inside Garmin’s tolerance window.

05 · Security advantages

Memory safety
is a security feature.

No GC pauses leaking timing. No eval, no dynamic dispatch on user input. No Python supply chain at runtime. Just a 10 MB binary you can audit.

01

Credentials at rest

Two paths: env vars or _FILE mode that reads ~/.garmin_email & ~/.garmin_password (chmod 600). Secrets never enter claude_desktop_config.json.

02

Type-safe sessions

No data race can produce a second OAuth session — the borrow checker rejects it at compile time. Send/Sync bounds carry through the whole tool registry.

03

Local stdio only

MCP runs over stdin/stdout under the host process. No exposed port, no network listener, no remote attack surface. Garmin traffic is HTTPS to one host.

04

Destructive ops omitted

delete_activity is intentionally not exposed — there is no irreversible verb an LLM can call by accident. get_activity_details (50–500 KB GPS) is also omitted to avoid leaking precise location.

05

Minimal supply chain

11 direct dependencies in Cargo.toml. Reviewable. No pip-installed transitive Python packages mutating themselves at runtime.

06

Rate-limit hardening

A model that loops accidentally cannot brick your account — the limiter caps Garmin-bound traffic before the first 429 ever arrives.
